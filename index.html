What it does

CNAB is the fixed-width file format Brazilian banks use to exchange cobrança instructions (remessa) and their results (retorno). Every field is defined by an absolute position on a 240- or 400-character line, and every bank varies the layout. Getting a position wrong doesn't throw — it produces a plausible, wrong number.

Parse

Read a whole file, detect bank/layout/direction per line, and get typed field maps back.

Generate

Build valid files with lote sequencing, record counters and trailer control fields computed for you.

Validate

Line length, field shape and check digits — módulo 10/11, barcode, linha digitável.

PIX

Generate, parse and CRC-verify the BR Code “copia e cola” payload behind the hybrid boleto.

Verify the spec

The build rejects any record whose fields don't cover the line completely, with no gaps or overlaps.

Strict by default

toLine throws rather than silently reshaping a value. Writing a 17-digit amount into a 15-wide field used to keep the rightmost digits and produce a different, entirely plausible amount that still validated. For a bank file that is undetectable financial corruption, so it is now an error naming the field, its positions and its width. The old behaviour is available explicitly via toLineWithOptions.

The references are generated from the jsii assembly the bindings are built from, so Python shows set_decimal(...), C# shows SetDecimal(...) and Java shows setDecimal(...) — the signature that language actually has, not a translation of the TypeScript one.

The Python, Java and .NET bindings need Node.js at runtime. This is how jsii works: the engine really is the TypeScript, and each binding starts an embedded node process (override with JSII_NODE) and talks to it. Node is a dependency of your application, not just of your build. The jsii runtime asks for Node ≥ 20.16, so that is the practical floor for non-Node consumers.

Quick start

Nothing is on a registry yet, so grab the artifacts from the latest release.

Node.js

npm install ./cnab-core-0.3.0.tgz

const { CnabSpec } = require('@cnab/core');

const spec   = CnabSpec.bundled();
const record = spec.getRecord('cnab240/104/sigcb/remessa/detalhe_segmento_p');

let values = {};
values = record.setDecimal(values, 'valor_titulo', '1500.00');
values = record.setDateIso(values, 'vencimento', '2026-07-15');

const line = record.toLine(values);          // 240 chars
const back = record.parse(line);             // { valor_titulo: '150000', ... }

Python

pip install ./cnab_core-0.3.0-py3-none-any.whl

import cnab_core as c

spec   = c.CnabSpec.bundled()
record = spec.get_record('cnab240/104/sigcb/remessa/detalhe_segmento_p')

values = record.set_decimal({}, 'valor_titulo', '1500.00')
line   = record.to_line(values)

Java

import org.cnab.core.*;

CnabSpec spec  = CnabSpec.bundled();
CnabRecord rec = spec.getRecord("cnab240/104/sigcb/remessa/detalhe_segmento_p");

Map<String, String> values =
    rec.setDecimal(new HashMap<>(), "valor_titulo", "1500.00");
String line = rec.toLine(values);

.NET

using Cnab.Core;

var spec   = CnabSpec.Bundled();
var record = spec.GetRecord("cnab240/104/sigcb/remessa/detalhe_segmento_p");

var values = record.SetDecimal(new Dictionary<string, string>(), "valor_titulo", "1500.00");
var line   = record.ToLine(values);
The setters return a new map; they do not mutate. setDecimal and setDateIso used to return void and write in place — which works only in Node, because jsii marshals maps by value. Always assign the result.

Command line

cnab records    --bank 104
cnab parse      --record cnab240/104/sigcb/header_arquivo < line.txt
cnab build      --record cnab240/104/sigcb/header_arquivo < values.json
cnab validate   --record cnab240/104/sigcb/header_arquivo < line.txt
cnab detect     < remessa.rem       # identify bank / layout / direction
cnab parse-file < remessa.rem --pretty
cnab tables                          # list code tables
cnab code       <tableKey> <code>    # look up one code

cnab boleto barcode --bank 104 --currency 9 --due 2026-07-15 \
                    --amount 150000 --free 0000000000000000000000000
cnab boleto parse   <linhaDigitavel>

Files are read and written as Latin-1 by default, because real CNAB files are ISO-8859-1/Windows-1252 and one character must equal one byte or every position after an accented name shifts. Use --encoding utf8, --crlf and --trailing-newline to match a bank's exact expectations.

How it is built

The design decisions are written down as ADRs and are binding — the short version:

  • One engine, authored once. Every language is a jsii projection of the same TypeScript, so behaviour cannot drift between them.
  • A field catalog plus full standalone records. The catalog holds semantics by canonical name and carries no positions; each record lists its complete positioned field set with no inheritance. The compiler then proves every line is fully covered, with no gaps or overlaps.
  • Exact values at the boundary. Decimals and dates cross as strings — "1500.00", "2026-07-15" — never floats.
  • Tested per language. Unit suites run against the generated Python, Java and .NET artifacts, not just the TypeScript, because a projection can break in ways the Node tests cannot see.
